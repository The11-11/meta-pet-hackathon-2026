# Meta Pet project brief

**Your pet's companion.** Current checkpoint: **3 November 2026**.

Meta Pet brings pet profiles, everyday observations and future care plans into one app. Muse Pet uses Meta models to help owners ask better questions and review useful next steps. A suggestion becomes a saved local action only after the owner approves it.

## Names

| Name | Role |
| --- | --- |
| Meta Pet | The app: profiles, care records, appointments, settings and social drafts. |
| Muse Pet | The AI companion inside the app. |
| Petaverse | The wider ecosystem vision and future connected products. |

Kai is the existing companion mascot. A custom generated portrait can represent a pet; the public rehearsal used clearly labelled sample artwork and a synthetic demonstration profile.

The [verification record](../apps/meta-pet/verification.json) preserves earlier counts and device limits.

- Real owner Facebook sign-in on the [public demo](https://petaverse-meta-pet-demo.vercel.app), live Muse Spark guidance, saved server page memory and same-browser sign-out/return have passed.
- Public Muse Image generation from nonprivate project artwork, explicit avatar selection and reload persistence passed. Earlier local tests used an approved pet photo. A permissioned real pet-photo test on the public path remains distinct.
- In the public rehearsal, Muse declined to invent a completed past walk. It prepared a future DEMO CHECK-IN for 4 November 2026 at 09:00 SAST; nothing was saved before approval. Approval saved one local appointment note, retained with the avatar after reopening. This does not book a vet.
- Ordinary owners can record real feeding, walks, training and rest. Muse's structured care or appointment proposals require explicit review and bounded validated inputs.
- Verified Facebook owners can review or clear bounded private memory per pet page. Full profile, care timeline and chat history remain device-local; private server memory is separate. Guest previews and token-only local chats do not access server page memory.
- Supply and trainer tools open controlled searches for owner review. Listings, prices, business suitability and availability are unverified. The collar, camera and feeder images are concept artwork.
- Social page plans and approved caption drafts retain the pet's @handle locally. The app does not create or publish Facebook or Instagram posts.
- Real CC0 bark and meow recordings work in web previews. Physical-device notification delivery and camera behavior remain unverified.

The separate local development coordinator can plan, consult specialists, propose a patch and obtain independent review. Applying a patch is a separate explicit local action. Public pet chat has no repository, computer or deployment privileges.

## Access and deployment boundaries

The Vercel frontend uses a same-origin API to an isolated backend through an approved temporary HTTPS tunnel. The host computer, backend and tunnel must remain running. Production model and memory endpoints require a verified Facebook session; a shared development token does not grant public access.

The Meta app remains unpublished: business verification is incomplete and Publish is disabled. Live Facebook testing is available to the owner and accepted testers; T's invitation remains pending. **Explore the demo** is a local preview with clear sign-in guidance for live features. Do not promise unrestricted reviewer login or cross-device profile synchronization.

Native installation, notification delivery, Facebook deep links, persistent unattended hosting and multi-instance memory storage remain separate checks. Collar audio/sensors, real purchases or coin transfers, Marketplace payments, trainer bookings, social publishing and WhatsApp delivery are unconnected.
